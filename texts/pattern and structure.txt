Design Patterns (Fully Implemented)

Factory Pattern
Used for: Creating all map rooms uniformly.
Implementation: schoolMapFactory.rpy defines a base Room class with common parameters (room_id, name, idle/hover images, xpos/ypos, label_name).
Every room (Dorm, Shop, Casino, Track, Courtyard, Gameroom, etc.) subclasses Room and is instantiated with addroom(RoomClass()).
Benefit: Centralized room creation, easy to add new rooms without duplicating code.

Command Pattern
Used for: Decoupling room entry logic from the map screen.
Implementation: command.rpy defines RoomCommand interface and CallRoom concrete command.
Each room stores self.command = CallRoom(self.label_name).
Map screen buttons execute Function(room.command.execute()).
Benefit: Allows flexible entry (new context vs. existing), easy to extend (e.g., locked rooms, conditions).

Singleton-like Pattern (Lazy Initialization)
Used for: The jumping minigame state.
Implementation: gameState.rpy uses a global default game = SimpleGameState() and reset_Jumpgame() reinitializes it.
Only one game instance exists at a time — classic singleton intent (with TODO to formalize later).

Event Queue / Priority Queue Pattern
Used for: Managing daily courtyard events.
Implementation: EventQueue.rpy + EventHandler.rpy
Events stored as list of dicts {time, name, priority}.
EventQueue.build() filters by day/time, skips completed events, sorts by priority descending.
pop() and execute in order.

Benefit: Deterministic, scalable event scheduling with easy insertion (priority gaps of 10).


Data Structures (Fully Implemented)

Dictionary (dict)
Global room registry: SchoolmapRooms = {} in schoolMapFactory.rpy — maps room_id → Room instance.
Purchased items tracking: default purchased_items = {} — maps item.name → True/False.
Event lists: mondayEvents and fridayEvents as lists of dicts.

List
Event queues: mondayEvents, fridayEvents — ordered lists of event metadata.
Puzzle images: puzzle_images = [...] including None for blank tile.

Set
Completed events: events_done = set() — fast O(1) lookup to prevent re-running events.

Enum (Python enum)
Shop items: class ShopItem(Enum) — clean, type-safe way to define items with label/price/desc.
Prevents typos and allows easy iteration.

Class-based Objects
Rooms (Room subclasses)
Game entities: JumpPlayer, Enemy, SimpleGameState
All hold state (position, velocity, grounded, passed, etc.)

Function Dictionary (Strategy-like)
Shop conditions: ITEM_CONDITIONS = {ShopItem.ITEM1: fakeidCondition, ...}
Maps items to unlock check functions — dynamic condition evaluation.

Notifications
